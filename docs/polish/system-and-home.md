## Audits after the pass

- Controls (`/`, `/missing-page`, phone and desktop): OK, same control and Tab-stop counts as before (the five hidden path panels add no Tab stops). Also OK on `/work/endorphins` and `/firms`, both sizes. The 404's console line is its own expected 404 status.
- Motion (dev server, so indicative): interactions and the phone menu drop no frames. Scrolling: on a first pass the home page drops about 1% on a phone and 2 to 4% on desktop, almost all in one or two frames; a second pass in the same page drops 0.0% on the phone (worst gap 19ms) and 0.7% on desktop. Traces show the first-pass frames are one-time GPU work in the headless software GPU (first raster and shader compilation, 110 to 140ms once), not per-frame work. The production build at 4x CPU is the real measure.
- `npx tsc --noEmit` and `npx eslint` on my files: clean.

## Not done, and why

- Page transitions (`<ViewTransition>`): left out. The work filter already drives view transitions with its own typed transitions and shared names, a layout-level cross-fade would interact with them and with the phone menu's exit (the old page's snapshot would carry the open menu while it also fades on the new page), and its conditions (no added delay, unchanged first-load numbers) need the production build to verify.
- Header hairline: its scroll-linked fade still runs on the main thread here (Chrome reports the scroll source as not composited in this headless setup); it is a 1px line and changes only over the first 24px.
- Loop posters load as soon as the page does (a poster is not lazy-loaded the way the video is); that belongs to the video loading pass.
